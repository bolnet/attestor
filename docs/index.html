Memory your agent mesh can be audited on.

When many agents share one memory, recall is the easy part. The hard part is who may write, who may forget, and what an answer was built from — and proving it later. Attestor enforces those in code, across Postgres, Pinecone and Neo4j.

Governance enforced in code, not in a policy document. Each row names the guarantee, what the code does, and the file that does it. If it is not in the code, it is not on this page.

Role-based access, six roles

ORCHESTRATOR may read, write and forget. PLANNER, EXECUTOR and RESEARCHER may read and write. REVIEWER and MONITOR read only. read_only=True strips write and forget regardless of role. A violation raises before any backend is touched.

Provenance on every memory

Every write carries agent, session, namespace and role; child contexts accumulate an agent trail, so "which agent said this, on whose behalf" is always answerable. The source episode is set by the consolidation path, not by every write. Supersession never deletes; rows leave only through an explicit forget, a retention delete policy, or compact(). Optional Ed25519 signing gives cryptographic non-repudiation, verified with verify_memory().

attestor/context.py · attestor/identity/signing.py

Per-agent budgets and write quotas

A token budget bounds what recall() packs for one context; it never limits writes. A per-context write cap (an in-memory counter that resets with a new context) and a per-user daily quota bound what can be added. The cap is a property of the context, so a misbehaving sub-agent is contained by construction.

attestor/context.py · attestor/core/agent_memory.py

Deterministic read path

Ranking is vector → BM25 → RRF → graph → MMR → budget fit, with no LLM in scoring by default. The optional reranker is off by default. Same query, same order — unit-testable, replayable, and explainable to an auditor line by line.

attestor/retrieval/orchestrator/core.py · scorer.py · reranker.py

Temporal supersession, as_of replay

Contradictions supersede older facts; supersession never deletes. Every fact carries valid time and transaction time. recall(as_of=…) filters candidates on transaction time at document hydration and in the BM25 lane; the Pinecone lane ignores as_of.

attestor/temporal/manager.py

Hard tenant isolation, all three stores

Tenant is the user. Postgres row-level security keyed to the current user, with namespace stamped into metadata; Pinecone one index with a namespace partition on every call; Neo4j namespace property with a composite constraint and namespace-scoped traversal. The PageRank projection is global and is a ranking signal only.

attestor/store/schema.sql · pinecone_backend.py · neo4j_backend.py

Auditable forget-user and retention

forget_user() writes an RLS-exempt, append-only by convention audit row before deleting, then walks document → state → vector → graph and reports per-backend counts, so partial success is visible rather than silent. Declarative retention policies (archive or delete) apply first and write the audit row after. Full export for subject-access requests.

Method, and honest scope

  • One unique code per memo (needle-in-a-haystack), retrieved top-1, no distractors — isolates "does the agent still have the fact?"
  • Native context window — models run at full capacity; capping is shown only to reproduce the cap-and-rot failure mode.
  • 100% recall = the right memo is reliably found and read — not a claim about hard multi-hop or conflicting-fact retrieval.
  • temperature 0, deterministic; real billed cost from OpenRouter usage.cost, never list-price math.
