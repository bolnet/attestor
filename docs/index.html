Memory your agent mesh can be audited on.

When many agents share one memory, recall is the easy part. The hard part is who may write, who may forget, and what an answer was built from — and proving it later. Attestor enforces those in code, across Postgres, Pinecone and Neo4j.

Recall is the easy part.

Any vector store can hand an agent something relevant. A mesh in production has a harder problem: the memory is shared, the agents are not equally trusted, and one day someone who was not in the room will ask how a decision was made.

Most memory layers leave the three questions on the right to the calling application. Attestor answers them in the memory layer itself, so every agent, every client, and every future engineer gets the same answer.

Who wrote this, on whose behalf?

Every memory carries the agent, session, namespace and role that produced it. Child contexts accumulate the trail; Ed25519 signing makes it non-repudiable.

Who is allowed to forget it?

Six roles, enforced before any backend is touched. Forgetting writes its audit row first, then walks every store and reports per-backend counts.

What did the system believe last Friday?

Contradictions supersede; nothing is deleted. Every fact has valid time and transaction time, and recall(as_of=…) replays the belief of any past moment.

Every write has an author. Every read has a ranking you can replay.

Governance enforced in code, not in a policy document. Each row names the guarantee, what the code does, and the file that does it. If it is not in the code, it is not on this page.

Role-based access, six roles

ORCHESTRATOR may read, write and forget. PLANNER, EXECUTOR and RESEARCHER may read and write. REVIEWER and MONITOR read only. read_only=True strips write and forget regardless of role. A violation raises before any backend is touched.

Provenance on every memory

Every write carries agent, session, namespace and role; child contexts accumulate an agent trail, so "which agent said this, on whose behalf" is always answerable. Supersession never deletes; rows leave only through an explicit forget, a retention delete policy, or compact(). Optional Ed25519 signing gives cryptographic non-repudiation, verified with verify_memory().

Per-agent budgets and write quotas

A token budget bounds what recall() packs for one context. A per-context write cap and a per-user daily quota bound what can be added. The cap is a property of the context, so a misbehaving sub-agent is contained by construction.

Deterministic read path

Ranking is vector → BM25 → RRF → graph → MMR → budget fit, with no LLM in scoring by default. The optional reranker is off by default. Same query, same order — unit-testable, replayable, and explainable to an auditor line by line.

attestor/retrieval/orchestrator/core.py · scorer.py · reranker.py

Temporal supersession, as_of replay

Contradictions supersede older facts; supersession never deletes. Every fact carries valid time and transaction time. recall(as_of=…) filters candidates on transaction time at document hydration and in the BM25 lane; the Pinecone lane ignores as_of and says so in the log.

attestor/temporal/manager.py

Hard tenant isolation, all three stores

Postgres row-level security keyed to the current user, with namespace stamped into metadata; Pinecone one index with a namespace partition on every call; Neo4j namespace property with a composite constraint and namespace-scoped traversal. The PageRank projection is global and is a ranking signal only.

Auditable forget-user and retention

forget_user() writes an RLS-exempt audit row before deleting, then walks document → state → vector → graph and reports per-backend counts, so partial success is visible rather than silent. Declarative retention policies (archive or delete) apply first and write the audit row after. Full export for subject-access requests.

How a read happens.

Six steps, in this order, every time. No model is asked to score anything unless you turn the reranker on. That is what makes a ranking something you can replay in front of an auditor.

  1. Vector candidates

    Cosine top-K from Pinecone, scoped to the caller's namespace. An optional HyDE lane can widen the net.

  2. Lexical candidates

    BM25 over Postgres full-text search, filtered on transaction time when as_of is set.

  3. Reciprocal-rank fusion

    Both lists fold into one rank with a fixed constant. No weights to tune, nothing learned.

  4. Graph affinity

    A bounded breadth-first walk in Neo4j, inside the namespace, adds a bonus for candidates connected to the query's entities.

  5. Diversity and decay

    Maximal marginal relevance removes near-duplicates; confidence decays with age and supersession.

  6. Budget fit

    Greedy pack to the context's token budget, best first. The payload is flat per call however long the conversation is.

Ask it what it injected.

Every recall can report the packed payload it just handed the model — from the CLI or in the MCP response — so the cost of memory is a number you read, not one you estimate. Full-context replay has to re-send a growing transcript each turn; this does not.

$ attestor recall ~/.attestor "what did we decide about auth?" --show-tokens [tokens] packed N tokens across M memories (cap budget). This payload is flat regardless of conversation length — full-context replay grows unbounded.

Built for the day someone asks.

Three situations where "the agent remembered something" is not an answer, and what you can say instead.

A security review is next quarter.

"Which of your agents can modify shared state, and how do you know a compromised sub-agent can't wipe it?"

Roles are enforced at the context layer, before any backend call. Forget is a separate permission from write. Budgets and write caps are properties of the context, so containment is by construction. The reviewer can read ROLE_PERMISSIONS and stop there.

A regulator can ask what the system believed on a date.

"Reconstruct the information your agent had when it made this recommendation on the fourteenth."

recall(as_of=…) returns the belief of that moment. Nothing was deleted to get there — later contradictions superseded earlier facts, and both are still in the log with valid time and transaction time. Provenance names the agent and session for every row.

It's 3 a.m. and an agent did something wrong.

"Which memory did it act on, who wrote that memory, and why did it rank first?"

The read path is deterministic: re-run the query with the same context and you get the same order, step by step. The memory carries its author, its session and, if signing is on, a verifiable signature. Then fix the fact, supersede it, and the next call sees the correction.

Runs where you run.

One API across three topologies. Only the configuration changes. Postgres is the source of truth; Pinecone vectors and the Neo4j graph are derived state, rebuildable from it.

Embedded library

AgentMemory(config) in process, talking directly to the three stores. The Claude Code plugin and MCP server run this way.

Sidecar

attestor api on localhost; any language talks HTTP to the same stores. RBAC stays an AgentContext guarantee; the REST surface relies on its own auth.

Shared service

One Attestor in front of a mesh — App Runner, Cloud Run or Container Apps — on managed Postgres, Pinecone and Neo4j.

Local, in one command.

Zero questions. It writes the config, brings up Postgres, Pinecone Local and Neo4j in Docker, wires the MCP server and hooks for Claude Code, and runs attestor doctor. attestor teardown reverses it and keeps your data unless you say otherwise.

$ pipx install attestor $ attestor quickstart

Provenance, all the way down.

A memory layer that sells auditability should be auditable itself. The repository is held to the same standard as the data it stores.

  • Every source file carries an SPDX header naming its author and licence, so a copy is a copy with a name on it.
  • Commits are SSH-signed and the repository runs in vigilant mode, so unsigned history shows as such.
  • Releases are timestamped on Bitcoin with OpenTimestamps — the .ots proofs ship in artifacts/provenance/ and verify offline against the chain.
  • No benchmark numbers in the repo. Figures go stale; the harness that produces them is open and you run it yourself.
