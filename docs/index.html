Recall is the easy part.

Any vector store can hand an agent something relevant. A mesh in production has a harder problem: the memory is shared, the agents are not equally trusted, and one day someone who was not in the room will ask how a decision was made.

Who wrote this, on whose behalf?

Every memory carries the agent, session, namespace and role that produced it. Child contexts accumulate the trail. Ed25519 signing makes it non-repudiable.

Who is allowed to forget it?

Six roles, enforced before any backend is touched. Forgetting writes its audit row first, then walks every store and reports per-backend counts.

What did the system believe last Friday?

Contradictions supersede; nothing is deleted. Every fact has valid time and transaction time, and recall(as_of=…) replays any past moment.

Every write has an author. Every read has a ranking you can replay.

Each guarantee below is a property of the code, with the file that enforces it. If it is not in the code, it is not on this page.

Access

Who may do what, decided before any store is touched.

Role-based access, six roles

ORCHESTRATOR may read, write and forget. PLANNER, EXECUTOR and RESEARCHER may read and write. REVIEWER and MONITOR read only, because a reviewer that writes contaminates the evidence trail. read_only=True strips write and forget regardless of role. A violation raises before any backend is touched.

Per-agent budgets and write quotas

A token budget bounds what recall() packs for one context. A per-context write cap and a per-user daily quota bound what can be added. The cap is a property of the context, so a misbehaving sub-agent is contained by construction.

attestor/context.py · attestor/core/agent_memory.py

Hard tenant isolation, all three stores

Postgres row-level security keyed to the current user, with namespace stamped into metadata. Pinecone: one index, a namespace partition on every call. Neo4j: a namespace property with a composite constraint and namespace-scoped traversal. The PageRank projection is global and is a ranking signal only.

Truth

What was said, by whom, and what the system believed at any moment.

Provenance on every memory

Every write carries agent, session, namespace and role. Child contexts accumulate an agent trail, so "which agent said this, on whose behalf" is always answerable. Rows leave only through an explicit forget, a retention delete policy, or compact(). Optional Ed25519 signing gives cryptographic non-repudiation, verified with verify_memory().

attestor/context.py · attestor/identity/signing.py

Temporal supersession, as_of replay

Contradictions supersede older facts; supersession never deletes. Every fact carries valid time and transaction time. recall(as_of=…) filters candidates on transaction time at document hydration and in the BM25 lane. The Pinecone lane ignores as_of and says so in the log.

attestor/temporal/manager.py

Deterministic read path

Ranking is vector, BM25, RRF, graph, MMR, budget fit, in that order, with no LLM in scoring by default. The optional reranker is off by default. Same query, same order: unit-testable, replayable, explainable to an auditor line by line.

Deletion

Forgetting that leaves a record. Jobs that finish.

Auditable forget-user and retention

forget_user() writes an RLS-exempt audit row before deleting, then walks document, state, vector and graph and reports per-backend counts, so partial success is visible rather than silent. Declarative retention policies (archive or delete) apply first and write the audit row after. Full export for subject-access requests.

Consolidation, derived-state rebuild, retention sweeps, session sweeps and the forget-user saga run as Temporal workflows with retry policies, resumable after a crash, visible in an operator UI. Opt-in; job state only. Postgres stays the source of truth. How it is wired.

How a read happens.

Six steps, in this order, every time. No model is asked to score anything unless you turn the reranker on. That is what makes a ranking something you can replay in front of an auditor.

  1. Vector candidates

    Cosine top-K from Pinecone, scoped to the caller's namespace. An optional HyDE lane can widen the net.

  2. Lexical candidates

    BM25 over Postgres full-text search, filtered on transaction time when as_of is set.

  3. Rank fusion

    Both lists fold into one rank with a fixed constant. No weights to tune, nothing learned.

  4. Graph affinity

    A bounded breadth-first walk in Neo4j, inside the namespace, boosts candidates linked to the query's entities.

  5. Diversity and decay

    Maximal marginal relevance removes near-duplicates. Confidence decays with age and supersession.

  6. Budget fit

    Greedy pack to the context's token budget, best first. Flat per call however long the conversation is.

Ask it what it injected.

Every recall can report the packed payload it just handed the model, from the CLI or in the MCP response. The cost of memory is a number you read, not one you estimate. Full-context replay re-sends a growing transcript each turn. This does not.

$ attestor recall ~/.attestor "what did we decide about auth?" --show-tokens [tokens] packed N tokens across M memories (cap budget). This payload is flat regardless of conversation length. Full-context replay grows unbounded.

The read path never waits. The jobs never quit.

Governance work that used to be a cron job and a prayer runs as Temporal workflows: retried by policy, resumed after a crash, inspectable in an operator UI. Turn it on with one flag.

Two hard rules. Recall never touches Temporal and hooks never wait on it; nothing under the retrieval or hook packages may import it, and a test enforces that. Workflow payloads carry ids, never memory content, so Postgres stays the only source of truth.

With durable.enabled: false, or an unreachable server, every job falls back to the in-process path it replaced. Nothing about a memory ever lives only in a workflow history.

Built for the day someone asks.

Three situations where "the agent remembered something" is not an answer, and what you can say instead.

A security review is next quarter.

Which of your agents can modify shared state, and how do you know a compromised sub-agent can't wipe it?

Roles are enforced at the context layer, before any backend call. Forget is a separate permission from write. Budgets and write caps are properties of the context, so containment is by construction. The reviewer can read ROLE_PERMISSIONS and stop there.

A regulator asks what the system believed on a date.

Reconstruct the information your agent had when it made this recommendation on the fourteenth.

recall(as_of=…) returns the belief of that moment. Nothing was deleted to get there: later contradictions superseded earlier facts, and both are still in the log with valid time and transaction time. Provenance names the agent and session for every row.

It's 3 a.m. and an agent did something wrong.

Which memory did it act on, who wrote that memory, and why did it rank first?

The read path is deterministic: re-run the query with the same context and you get the same order, step by step. The memory carries its author, its session and, if signing is on, a verifiable signature. Fix the fact, supersede it, and the next call sees the correction.

Runs where you run.

One API across three topologies; only the configuration changes. Postgres is the source of truth. Pinecone vectors and the Neo4j graph are derived state, rebuildable from it.

Embedded library

AgentMemory(config) in process, talking directly to the three stores. The Claude Code plugin and the MCP server run this way. Role enforcement is an AgentContext guarantee and runs in process.

Sidecar

attestor api on localhost. Any language talks HTTP to the same stores.

Shared service

One Attestor in front of a mesh on App Runner, Cloud Run or Container Apps, backed by managed Postgres, Pinecone and Neo4j.

Local, in one command.

Zero questions. It writes the config, brings up Postgres, Pinecone Local and Neo4j in Docker, wires the MCP server and hooks for Claude Code, and runs attestor doctor. attestor teardown reverses it and keeps your data unless you say otherwise.

Provenance, all the way down.

A memory layer that sells auditability should be auditable itself. The repository is held to the same standard as the data it stores.

  1. Every source file carries an SPDX header naming its author and licence, so a copy is a copy with a name on it.
  2. Commits are SSH-signed and the repository runs in vigilant mode, so unsigned history shows as such.
  3. Releases are timestamped on Bitcoin with OpenTimestamps. The .ots proofs ship in artifacts/provenance/ and verify offline against the chain.
  4. No benchmark numbers in the repo. Figures go stale. The harness that produces them is open, and you run it yourself.

If your memory layer cannot show you the enforcing line, it is a policy document.
